# Accounts and credentials — Dhruv's checklist

Accounts are created by Dhruv, not by the coding assistant. Use the shared team email, enable 2FA where available, save recovery codes and credentials in the shared password manager, and invite both teammates as collaborators where supported. Separate staging/demo keys where possible. Rotate keys after the event. Never paste a key into chat or Git.

## Ordered setup

1. **Team access.** Create shared email/vault, add teammates, store 2FA recovery codes, and document who can recover accounts.
2. **GitHub.** Use [bhattarya/Cooked](https://github.com/bhattarya/Cooked). Invite teammates. In Settings → Rules/Branches, protect `main`: require PR review, current branch, status checks `Database and API`, `Web build`, `Secret scan`; disallow force pushes and deletions. Choose check names after the first workflow has run. Enable Actions. Keep deployment permissions with Dhruv.
3. **Tiger Cloud.** Sign up at [Tiger Data](https://www.tigerdata.com/cloud), create a dedicated `cooked` service near US East. Record plan/limits/version in `SETUP_STATUS.md`. Put the service administrator connection string in `DATABASE_URL` (this is the migration-owner connection, possibly named `tsdbadmin` by the service). Preserve TLS settings. Choose app/agent passwords in the vault, create the other two URLs using the same host/port/database and usernames `app_rw`/`agent_ro`. Run `make migrate`, `make load`, `make test`, and `python -m scripts.smoke_tiger` using the venv. The code creates roles and sets passwords. After testing, give API/worker only app access; give agent tooling only agent access. Do not give the browser any DB URL.
4. **DigitalOcean.** Sign up through [MLH's DigitalOcean link](https://mlh.link/digitalocean-signup). Verify the credit on the billing page; create project `cooked`. Connect the GitHub repo. Follow [deployment instructions](deployment.md) for API, web and worker. Dashboard setup needs no API key. A token is needed only if enabling the CI trigger; keep it in GitHub Actions secrets, not application runtime variables.
5. **Gemini.** Open [AI Studio API keys](https://aistudio.google.com/api-keys), select/create the team project and key. Choose a Flash model the account actually offers on its free tier; copy the model identifier into `GEMINI_MODEL`. Record the [active rate limits](https://ai.google.dev/gemini-api/docs/rate-limits). Send synthetic test content only: [pricing/data-use terms](https://ai.google.dev/gemini-api/docs/pricing) distinguish free and paid use. Run the Gemini smoke script once; record model, latency, quota and date. Do not enable paid billing automatically.
6. **Backboard.** At [app.backboard.io](https://app.backboard.io), Settings → API Keys, create a team key. Configure `BACKBOARD_BASE_URL=https://app.backboard.io/api`. Authentication uses `X-API-Key`. Record trial credit/expiry from the account's [billing view](https://docs.backboard.io/concepts/billing). Run cross-thread smoke test; it creates and deletes its own temporary assistant. No custom model routing/provider keys are configured.
7. **ElevenLabs.** At [ElevenLabs](https://elevenlabs.io), create an API key with text-to-speech and subscription-read permissions for the smoke test. Pick accessible Narrator and Coach voices; store IDs. Select a TTS model using the [API reference](https://elevenlabs.io/docs/api-reference/text-to-speech/convert), then set `ELEVENLABS_MODEL`. Check [plan pricing](https://elevenlabs.io/pricing/api) and attribution terms for the actual plan. Run the 200-character smoke test, listen to `data/smoke/elevenlabs.mp3`, and record usage-counter delta. Add “Voice by ElevenLabs” before shipping audio. Do not subscribe to a paid plan without team agreement.
8. **Google sign-in.** In [Google Cloud Console](https://console.cloud.google.com/) pick or create the team project. Under *APIs & Services → OAuth consent screen*, choose *External*, fill the app name (COOKED) and support email, add scopes `openid`, `email`, `profile`, keep it in *Testing* and add each teammate and judge as a test user. Under *Credentials → Create credentials → OAuth client ID*, choose *Web application* and add the authorized redirect URIs `http://localhost:3000/auth/callback/google` and `https://<deployed web URL>/auth/callback/google`. Put the client ID and secret in `.env` as `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` (and in DigitalOcean as web runtime secrets, plus `AUTH_URL=https://<deployed web URL>`). `AUTH_SECRET` is generated by `make env`; use a different random value in production. Restart `make dev-web`; the landing page switches from "Continue as guest" to "Continue with Google".
9. **Devpost.** Register all three teammates, select the Career Pathways & Degree ROI track, and verify opt-ins for ElevenLabs, Gemini, Backboard, Tiger Data and DigitalOcean. Confirm whether multiple sponsor tracks are allowed and whether separate demos are required. Add repo/video/HTTPS URLs when available; this document does not claim registration is complete.

`.env.example` additionally includes local DB settings, `MODEL_ARTIFACT_DIR`, `DEMO_MODE`, `CORS_ORIGINS`, `NEXT_PUBLIC_API_URL`, and deployed smoke URLs. The provider smoke scripts require no new framework or SDK.
